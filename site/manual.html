1. Getting started

Install the prebuilt binary (Linux x86_64, macOS aarch64) into ~/.local/bin; TRUG_INSTALL_DIR changes the directory and TRUG_VERSION pins a release:

curl -fsSL https://udoprog.github.io/trug/install.sh | sh

On Windows, download the zip from the releases. Builds target wasm32-unknown-unknown, so add it once with rustup target add wasm32-unknown-unknown.

A minimal app is a crate with an index.html beside its Cargo.toml:

my-app/
  Cargo.toml
  index.html
  src/lib.rs        # or src/main.rs
  style/app.scss
<!doctype html>
<html>
<head>
  <link data-trug rel="rust" href="Cargo.toml">
  <link data-trug rel="scss" href="style/app.scss">
</head>
<body></body>
</html>

Then, in my-app:

trug serve            # build, serve on 127.0.0.1:8080, rebuild on change
trug build --release  # optimized build into dist

No Trug.toml is needed: without one trug builds index.html in the current directory into dist beside it. The crate is a cdylib library or a binary; a cdylib wins when both exist.

2. Commands

trug build [-c Trug.toml] [-d DIR] [--release] [-j N] [--public-url /app/]
trug serve [--no-watch] [--ignore GLOB]... [--address ADDR]... [--port N] [build flags]
trug clean [-c Trug.toml] [-d DIR] [--cargo [--manifest-path Cargo.toml]] [--tools]
trug css STYLESHEET [-o OUT] [-I DIR]... [--style expanded|compressed] [--embed-source-map]
trug packages
trug update

trug build

Runs the hooks, builds the crate, runs wasm-bindgen (and wasm-opt on --release), compiles the styles, rewrites index.html and replaces dist, only if every step succeeded.

FlagMeaning
-c, --config FILEThe Trug.toml to use; Trug.toml in the current directory by default, and the defaults without one.
-d, --dist DIROutput directory, relative to the current directory; overrides [build] dist.
--releaseCargo release profile, wasm-opt, no source maps.
-j, --jobs NPassed to cargo as --jobs.
--public-url URLPrefix of every URL in the output index.html; overrides <base data-trug-public-url>, default /.

Cargo flags

build, serve, css and packages take the app's cargo flags, so features resolve as in the build:

--manifest-path FILEThe app's Cargo.toml.
--target TRIPLEDefault wasm32-unknown-unknown.
-F, --features A,BFeatures to enable; repeatable or comma-separated.
--all-features, --no-default-featuresAs in cargo.
--locked, --offlineAs in cargo.

trug serve

Takes every build flag and cargo flag, plus:

--no-watchServe the first build only: no watching, no reload script.
--ignore GLOBRepeatable; adds to [watch] ignore for this run, relative to Trug.toml.
--address ADDRRepeatable; overrides [serve] addresses.
--port NOverrides [serve] port; 8080 by default.

trug clean

Removes dist (found as build finds it, with -c and -d) and the staging directories beside it; a missing dist is not an error. --cargo also runs cargo clean (with --manifest-path for the app's Cargo.toml) and --tools also removes the tool cache. Nothing else is removed.

trug css and trug packages

trug css builds just a stylesheet with pkg: URLs: -o writes it atomically (stdout without it), -I/--load-path adds directories plain @use URLs resolve against, --style is expanded (default) or compressed, and --embed-source-map appends an inline source map with the sources in it. trug packages lists the crates that ship styles, with their enabled features.

trug css style/app.scss -o dist/app.css -F extra --style compressed

trug update

Replaces the running binary with the latest GitHub release for this platform, or says it is up to date.

Output flags

Every command takes --color auto|always|never (auto colours a terminal unless NO_COLOR is set), -q/--quiet (only warnings and errors; cargo runs quiet) and -v/--verbose (also the commands trug runs and the tools it uses).

3. Trug.toml

Every key is optional, unknown keys are errors, and paths are relative to the Trug.toml.

[build]
target = "index.html"   # default
dist = "dist"           # default: beside target
wasm_opt = true         # default; false skips wasm-opt on --release builds

[[hooks]]               # repeatable; run in order before the build
stage = "pre_build"     # the only stage
command = "cargo"
command_arguments = ["run", "-p", "tools"]

[serve]
addresses = ["127.0.0.1"]   # default
port = 8080                 # default
headers = { "Cross-Origin-Opener-Policy" = "same-origin" }  # added to every response

[watch]
watch = ["."]           # default: the directory of Trug.toml
ignore = ["target"]     # globs whose changes are ignored
debounce_ms = 200       # default

[[proxy]]               # repeatable, see Proxies
backend = "http://127.0.0.1:3000/api"
rewrite = "/api"
no_redirect = false
ws = false
change_origin = false

Hooks run in the Trug.toml's directory with stdin closed and TRUG_STAGING_DIR set to the staging directory the build writes to. A failing hook fails the build.

4. index.html directives

trug reads <link data-trug rel="..."> elements, replaces them with what they produce and removes them from the output. href is relative to index.html.

relDoes
rustThe crate to build, at most one. href is the crate directory or Cargo.toml, default Cargo.toml.
scssCompiles Sass with pkg: URLs; a source map with the sources in dev builds, none with --release.
cssCopies a plain stylesheet.
copy-dirCopies a directory into dist, at data-target-path (a relative path inside dist) or the directory's own name.
iconCopies the icon and links it.

Any other rel is an error. Styles and icons get content-hashed names, as do the app's <name>_bg-<hash>.wasm and <name>-<hash>.js (<hash> is 16 hex digits of the sha256).

<base data-trug-public-url href="/app/"> sets the URL prefix the output uses; --public-url overrides it.

5. Sass from crates

A crate ships Sass by opting in, in its Cargo.toml. The style directory must be in the package's include so it is published. Crate names match with - and _ alike.

[package.metadata.trug]
dir = "style"          # default; the style directory
entry = "_index.scss"  # default; inside dir

[package.metadata.trug.gate]
buttons = "button"     # _buttons.scss is empty unless feature "button" is on
  • @use "pkg:<crate>" as x loads the crate's entry. sasso needs an explicit namespace here (as x or as *).
  • @use "pkg:<crate>/<path>" loads a stylesheet in the crate's style directory; partials, .scss and index files resolve as in Sass, and the path stays inside the crate.
  • @use "pkg:<crate>/features" as f is generated: f.$features (enabled features to true), f.enabled($name), f.$name and f.$version.
  • Any other URL resolves relative to the containing file, then the -I load paths. Inside a crate, relative imports stay in that crate, and a file reached by two routes loads once.
@use "pkg:sockel/features" as f;
@if f.enabled("table") {
  .table { ... }
}

A gated file loads as an empty stylesheet when its feature is off, through pkg: and relative loads alike, so it should only emit CSS. An unknown feature or a key that names no file is an error. Features come from cargo metadata run with the app's flags, matching cargo tree -e features.

6. Build tools

trug fetches its tools once into its cache: $TRUG_CACHE_DIR, else $XDG_CACHE_HOME/trug, else ~/.cache/trug. Later builds need no network.

  • wasm-bindgen, at exactly the version in the app's Cargo.lock: wasm-bindgen on PATH if it is that version, else the cache (wasm-bindgen/<version>/), else the prebuilt release checked against its sha256, else cargo installed into the cache.
  • wasm-opt, run as wasm-opt -Oz on --release builds unless [build] wasm_opt = false; dev builds never run it. wasm-opt on PATH, else binaryen at a version pinned in trug (binaryen/<version>/), downloaded and checked against its sha256. Without one trug warns and stages the wasm unoptimized.

7. Dist, serving and live reload

Every build writes to a staging directory beside dist (a hidden .<dist>.trug-staging-* directory), which replaces dist in one rename only when the build succeeded. A failed build leaves the previous dist as it was; trug clean removes leftover staging directories.

trug serve builds once, serves dist and rebuilds on change:

  • It listens on 127.0.0.1:8080 unless [serve] or the flags say otherwise, and adds [serve] headers to every response.
  • Unknown paths without an extension get index.html, so SPA routes work. With a public URL, files are also served under it.
  • It watches [watch] watch (the Trug.toml directory by default). dist, its staging directories, target and .git are always ignored, as is a write that leaves a file's content unchanged.
  • A change starts one rebuild after debounce_ms of quiet. Builds run one at a time; changes during a build queue one more.
  • Index pages get a script listening on /_trug/reload (server-sent events). The page reloads after each successful build; a failed build keeps the last good page and shows the error in an overlay on it, dismissed with a click.

8. Proxies

[[proxy]] tables forward requests under a path prefix to a backend, before static files and the SPA fallback:

[[proxy]]
backend = "http://127.0.0.1:8150/api/"
no_redirect = true

[[proxy]]
rewrite = "/ws"
backend = "ws://127.0.0.1:8160/ws"
ws = true
backendThe backend URL; its path is the mount prefix unless rewrite is set.
rewriteThe prefix trug serves, replaced by the backend's path.
no_redirectHand backend redirects to the client instead of following them.
wsProxy WebSockets; backend is a ws:// URL (no TLS). Frames are piped both ways; subprotocols are not negotiated.
change_originRewrite the request's Origin header to the backend's origin.

Request headers (cookies, Origin, ...) go to the backend. A backend that is down gives 502.

9. Moving from trunk

Three renames; trug does not read the data-trunk forms:

trunktrug
Trunk.tomlTrug.toml
<link data-trunk rel="..."><link data-trug rel="...">
<base data-trunk-public-url><base data-trug-public-url>

Only the rel values in directives are supported. The output differs: no SRI integrity attributes, no window.wasmBindings, no TrunkApplicationStarted event, the wasm is <name>_bg-HASH.wasm (trunk: <name>-HASH_bg.wasm), and there is no .trunk-lock.
